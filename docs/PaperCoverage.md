## Conventions and fidelity requirements

* The paper explicitly permits loops and parallel edges (page 2). Edge identities must survive all constructions. `SimpleGraph` alone is insufficient.
* A loop contributes two to degree, but the paper's explicit set `δ(v) = {e : v is an end of e}` contains a loop only once. These are different notions. The distinction causes two literal false statements below.
* A cover is an indexed family or list, allowing repeated edge sets. In particular, covering a loop twice requires two occurrences of its one-edge cycle. A set of distinct subgraphs changes the statement.
* A cycle is a connected 2-regular subgraph, including a one-loop cycle and a cycle of two parallel edges. Eulerian subgraphs may be disconnected or empty.
* The proofs use finite edge counts, finite sums, finite matrices, minimum counterexamples by edge count, and finite matroid ground sets. A finite graph/finite matroid implementation must make this scope explicit. The paper does not separately state a universal finite-graph convention, so an extension to infinite objects must not be claimed from a finite implementation.
* Edge connectivity is explicitly defined only for graphs with at least two vertices. Empty graphs and one-vertex bouquets still occur in the general bridgeless statement and must be covered separately.
* General nowhere-zero flows use an orientation and count a loop once incoming and once outgoing. Unsigned incidence sums in characteristic two agree with flow conservation only after a correct loop convention or a loopless restriction.
* The final dependency closure must have no `sorryAx` or introduced mathematical axioms. Report the allowed standard Lean logical axioms: `propext`, `Classical.choice`, and `Quot.sound`.
* The surface model uses compact connected Hausdorff second-countable surfaces with plane charts. Edge paths have simple interiors, including closed paths for loops. A face is a connected component of the graph complement. A strong face includes an embedded closed-disk attachment whose boundary is the graph cycle; a frontier set alone would not record whether a face boundary traverses an edge twice. The surface definition includes no two-face-incidence or cycle-cover assertion.

## Literal defects and edge cases

### Lemma 8 is false with the stated incident-edge set and allowed loops

Take the graph with vertices `u,v`, one ordinary edge `a = uv`, and one loop `ℓ` at `v`. Its spanning tree has edge set `{a}`. Since `E(G) \ E(T) = {ℓ}`, every candidate `F` contains `ℓ`. At `u`, `δ(u) = {a}`, so even `|F ∩ δ(u)|` forces `a ∉ F`. Then `F ∩ δ(v) = {ℓ}` has odd cardinality. Thus there is no required `F`.

The one-vertex one-loop graph gives an even smaller example, with the empty spanning tree. The two-vertex example avoids any convention about trees on one vertex. The same defect also persists in a triangle with an added loop: an even incident-set count at each vertex would force the total incidence count to be even, while including exactly one loop makes that total odd.

A valid repair is to restrict Lemma 8 to loopless graphs, or to replace the incident-set cardinality condition by even degree with endpoint multiplicities. The user authorized correction, and the chosen formalized version has a loopless hypothesis. Its use in the cubic 3-edge-connected argument is loopless: in a cubic graph a loop leaves only one other incident edge, making that edge a bridge.

Status: **literal statement kernel-refuted** by `CycleDoubleCover.lemma8_literal_counterexample`, with the empty spanning tree checked in `oneLoopGraph_empty_spanningTree`. **Authorized corrected theorem kernel-checked** as `MultiGraph.IsSpanningTree.exists_incident_even_superset` in `TreeParity.lean`. The stronger endpoint-degree version `ConnectedOn.exists_eulerian_superset` also handles loops.

### Proposition 14 is false with loops

Take one vertex `v`, one loop `ℓ`, `F = F₂`, `W = F₂²`, `p_ℓ = (1,0)`, and `d_ℓ = (0,1)`. The vector `p_ℓ` is nonzero and the required dimension is `n = 2`.

Condition (i) requires `t_v + t_v ∈ d_ℓ + span(p_ℓ)`. In characteristic two the left side is zero, while the affine line on the right consists of `(0,1)` and `(1,1)`, excluding zero. Thus (i) is false.

Condition (ii) is true: its vertex condition is `Σ_{e ∈ δ(v)} h_e = h_ℓ = 0`, so the only admissible `h` is zero, and `h_ℓ · d_ℓ = 0`. Consequently (i) and (ii) are not equivalent.

The proof's block matrix places `R_e` in the column of an incident vertex once, whereas the equation `R_e(t_u+t_v)` places it twice for a loop. The displayed regrouping of the double sum has the same defect. This is not an issue with nondegeneracy in characteristic two: the ordinary dot product is nondegenerate over every field.

A valid repair is a loopless hypothesis, or a vertex conservation condition using endpoint multiplicities (the loop coefficient is two). The user authorized correction, and the chosen formalized version has a loopless hypothesis. The application in Proposition 15 is loopless. The corrected general-field loopless criterion must not be advertised as a proof of the literal PDF statement.

Status: **literal counterexample kernel-checked** by `proposition14_loop_primal_false`, `proposition14_loop_dual_true`, and `loopDirection_nonzero`. The dual theorem expresses the reduced single-loop incidence constraint `h = 0`; the primal theorem checks the equivalent scalar-span equation. **Authorized corrected criterion kernel-checked** as `MultiGraph.elementary_consistency_criterion` and its affine scalar form in `Consistency.lean`, over arbitrary fields and finite coordinate spaces.

The displayed assertion that every part has boundary at least `2k` only applies when there are at least two parts. The one-part tree-packing inequality is trivial and must be handled separately.
* Theorem 23: the sentence about covering loops "twice" is incompatible with its required four occurrences. ## Remaining topological constructions

U03's logical implication is proved independently in `EmbeddingImplications.lean`. The PDF's additional face-boundary construction would require a two-sided local neighborhood for an interior point of an embedded edge in a plane chart. The two sides give two face incidences. An embedded closed-disk face attachment must use one side once; it cannot count both sides as two traversals of the same boundary cycle. Each strong face has a nonempty graph cycle boundary, so counting edge sides would also prove that there are finitely many faces. Their boundary cycles would then give exact multiplicity two. Extending that stronger construction to arbitrary bridgeless graphs would require a proved block decomposition, with loop and two-parallel-edge blocks handled explicitly.

For U04, the indexed strict CDC now constructs an actual compact connected Hausdorff second-countable surface with genuine plane charts at every point.
